adversarial resilience dashboard — can your fraud detector be fooled by AI?

How fraudprobe works

A fraud model can look excellent on paper — 95%+ accuracy — yet have never faced an adaptive attacker. fraudprobe simulates one cheaply, using either simple math rules or a local LLM, and measures how much of that accuracy actually survives.

The pipeline

  1. Baseline — trains a classifier (XGBoost / Random Forest / GBDT) on transaction data and measures clean-conditions performance: F1, PR-AUC, recall on held-out fraud.
  2. Seed selection — pulls the frauds the model catches with ≥95% confidence from the held-out set. These are the "obvious" frauds — the ones you'd assume are safely caught.
  3. Adversary — mutates each seed fraud so it moves the same money but looks less suspicious, using one or more strategies:
    • amount_split — breaks one large transfer into several smaller ones summing to the same total.
    • temporal_dispersion — shifts the transaction to a less suspicious hour.
    • balance_camouflage — leaves a small residual balance instead of draining the account to exactly zero (a strong fraud signal in this data).
    Two backends generate these: rules (deterministic, instant) or llm (a local llama3 model does the same job in natural language — slower, and every output still has to pass an economic-validity check before being accepted).
  4. Stress test — rescoring the mutated corpus with the same baseline model and comparing detection: clean vs. adversarial, the point-drop in recall, and which strategy evaded most.
  5. Explain (SHAP) — for each feature, how much it pushed the model toward "fraud" on the original catches vs. the mutated versions. The biggest drops are the levers the attacker pulled.

How to read the results

  • Headline tiles — Clean detection is real recall on obvious fraud; Adversarial detection is recall after mutation. Detection drop-off is the percentage-point gap — the number that matters most. A large drop means the model leans on signals that are trivially game-able.
  • Weakness ranking — which mutation strategy evaded most, worst first. If amount_split dominates, the model over-relies on absolute transaction size rather than behavioural pattern.
  • SHAP evasion levers — blue is a feature's fraud-pushing signal on the original fraud; orange is the same feature after mutation. A feature whose orange bar collapses toward zero is a signal the attacker successfully neutralised — literally why the model got fooled, not just that it did.
  • Sample evading transactions — concrete rows with the model's real fraud score. A row scored 0.000 and marked "evaded" is a real fraud the model was fully confident was legitimate.
  • Compare mode's head-to-head strip — states which backend evaded more. With very few seed frauds, results get noisy (e.g. a single seed can flip the outcome); use a seed count of 20–30+ before trusting a comparison verdict.
